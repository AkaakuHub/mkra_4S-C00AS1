# 制限事項

## 受信と方式切り替え

- 物理チューナーは1基です。同じTSへの接続は共有しますが、異なるTSへの同時要求はHTTP503になります。
- 通常BSの主サービスとBS4Kを対象にしています。CS・地上デジタル・BS8K・全有料サービスの受信は保証しません。
- 2K/4K切り替えに伴う受信停止の修正は検証中です。長時間運用は未確認です。
- BS2K切り替え後のHDMI映像復帰は未解決です。HTTP配信の復帰とは別の問題です。
- 純正実行ファイルのハッシュと固定ABIを使うため、他のファームウェアや類似機種には対応しません。

## CASとTS品質

BS4Kは純正で復号したESをREMUXします。BS2Kは内蔵CASと通信し、CPUでMULTI2復号します。未知PIDや未対応ECMに属するパケットは暗号化フラグを維持します。サービスごとの完全なPID分離と、全多重の完全復号は保証しません。

受信開始時には映像・音声のデコード警告が残ります。HTTP200とコーデックの認識だけで、無欠損の録画を確認したとは扱いません。

## 電源制御

本体の`freeze`待機とMagic Packetによる復帰に対応します。深い`mem`待機と電源断からの起床には対応しません。純正映像ドライバーのPMコールバックを除外しており、消費電力と削減W数は未測定です。[電源制御](../tools/contrib/power/README.md)を参照してください。

## 番組表と録画

- EPG巡回もチューナーを使用します。即時録画との競合を完全には防げません。
- 番組IDによる配信の終了はキャッシュの時刻に基づき、延長・時刻変更への継続追従は未完成です。
- 最後の接続終了後も約3秒の解放待ちがあります。単一チューナーの連続予約では開始遅延や先行番組の末尾短縮が発生します。
- 本体の番組数カウンターは互換表示です。番組情報は`/api/programs`で確認してください。

## 運用

配置先はRAMです。再起動後は外部ホストから再投入してください。大きな録画・アーカイブ・ダンプは本体へ保存せず、外部ホストへ保存します。

認証・TLS・Mirakurunの全機能との互換性は提供しません。`gr`・`demux`・`tsrec`・`fem-dev`などの診断コマンドは受信状態を変更するため、日常の復旧手順として無作為に実行しないでください。[トラブル対応](TROUBLESHOOTING.ja.md)を参照してください。
