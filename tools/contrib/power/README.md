# AS1の本体待機とWake-on-LAN

本体の`freeze`待機から、LANのMagic Packetで同じ起動へ復帰させます。Linux・純正ドライバーの修正はRAM上へ適用し、再起動すると消えます。純正ファームウェアの書き換えは行いません。

## 導入

1. [カーネルモジュール](kernel/README.md)をビルドします。
2. AS1を新しく起動し、`kernel/apply.py`でモジュールを転送・照合・適用します。
3. 通常の受信サーバーへ`--wol-idle 60`を追加します。

```sh
/tmp/mt/mkra serve --remux4k --tune --bs2k --wol-idle 60 --channel-type BS4K --port 40772
```

録画終了と後処理から60秒以上経過し、確立済みTCP接続がない場合に待機します。親PCは録画開始前に、AS1のMACアドレス宛てのMagic Packetをブロードキャストし、APIの準備完了を待ってから配信を要求してください。

## 制限

- 対応する待機は`freeze`です。深い`mem`待機や電源断からの起床には対応しません。
- 純正映像ドライバーのPMコールバックは除外しています。消費電力と削減W数は未測定です。
- BS2K受信中は純正UIの競合選局を拒否します。受信終了後に解除し、4Kへ切り替えます。
- 回復監視にはLinuxのスケジューラーと純正マイコン監視経路が動くことが必要です。

`keep_awake.pl`は、検証済みの純正`abs`を照合し、RAM上のクイック起動設定と無操作オフ設定を確認・変更します。本体待機のモジュールと組み合わせて使います。永続設定を書き換える処理は含みません。
