# AS1の本体待機とLAN起床

Linux3.10.24の`freeze`と純正ドライバーを修正し、Magic Packetで本体処理へ復帰させます。純正マイコン監視の2スレッドとUARTは動かし続けます。表示PMは実行し、映像PMは復帰後の受信を維持するため除外します。消費電力は未測定で、深い`mem`待機は実装していません。

## ビルドと適用

```sh
make BUILD_DIR=/path/to/build
python3 apply.py --host 198.51.100.10 --module-dir /path/to/build --codec-bypass
```

対象はMD5が`1a3fdfa8379d75a802190b48ea951e9a`の純正`abs`と、SHA-256が`01c2e43c03fbd7404fd965493ee4088a9f36812485c7ea0aa146e61bc28bbef7`の純正`xcdrv.ko`です。カーネルのヘッダーは配布されておらず、ARM32のABIは保存済みの純正モジュールとカーネルの逆アセンブルから照合しています。`struct module`は360バイト、初期化関数は`0xbc`、スレッドスタックは8192バイトです。他機種向けではありません。

`apply.py`は新しい起動でのみ実行します。カーネル・純正実行ファイル・監視スレッドを照合し、モジュールをRAMへ転送してMD5を照合後、有効にします。既存の`as1_`モジュールがあれば拒否します。待機自体は実行しません。親PCからの利用には`apply_modules`を提供しています。

修正はRAM上だけで、再起動すると失われます。アンロードは提供していません。親PCの受信準備処理が再起動後に再適用します。

## 各モジュールの役割

| モジュール | 修正内容 |
| --- | --- |
| `as1_freezer` | 純正の待機処理からの`schedule`をfreezerに協調させます。既存の待機スレッドは全プロセスの`wchan`を調べ、`wake_tid`で再待機させます。 |
| `as1_display` | HDMI用mutexをfreezer前に確保し、純正表示停止へ渡します。freezerで中断された取得は復帰後に再試行します。純正表示の停止・再開を除外しません。 |
| `as1_wake` | IRQ83へ`IRQF_NO_SUSPEND`を加え、純正PMT通知から`freeze_wake`を呼びます。GMACレジスターは純正`plat_ReadReg`による間接アクセスです。 |
| `as1_lan` | 純正LAN PMをMAC単独の停止・復帰へ変更し、ネットワーク管理情報とDMAの破棄を避けます。 |
| `as1_front` | 純正`abs.T_FPD`と`abs.T_FPD3`だけを停止対象から外し、IRQ86を維持します。`console_suspend=N`で純正UARTも維持します。 |
| `as1_mmc` | 内蔵eMMCのホスト・カード・純正関数表を照合し、`MMC_CAP_NONREMOVABLE`と純正`mmc_ops_unsafe`を選び、マウント中のカード切り離しを防ぎます。 |
| `as1_codec` | `bypass=1`で純正映像ドライバーの停止・再開を両方除外します。これを実行した構成ではP4通知が残り、復帰後の受信がHTTP503になりました。 |
| `as1_guard` | PM開始から45秒の遷移を監視します。実際のfreeze待ちキューに入っている間は期限を進めず、停止時に純正監視通信を止めて回復を要求します。 |
| `as1_tuner` | BS2Kの受信開始から後処理完了まで、純正`abs.T_UIM`によるデバイス0の競合選局を`EBUSY`で拒否します。ADSBのキュー番号は起動ごとに解決します。 |

命令の変更は対象命令・呼び出し先・分岐範囲を照合し、`stop_machine`と各CPUの命令キャッシュ同期で適用します。固定eMMCへの設定はホストをclaimして変更します。

`as1_tuner`はBS2Kを使用する場合にも必要です。受信サーバーが所有期間を管理し、4Kへの復帰前に解除します。後処理に失敗した場合は所有を保持し、次の選局を停止します。純正ソフトによる選局とHTTP受信の同時使用はできません。

`as1_guard`は最優先のPM通知で監視を開始します。待ちキューのABIは実機の`prepare_to_wait`と`suspend_devices_and_enter`の命令列から照合します。カーネル内の監視スレッドが動くことは必要です。45秒の期限後に純正`abs`へSIGSTOPを送り、純正監視停止に続く本体再起動を利用します。マイコン内部のリセット理由は直接読んでいません。

## 自動待機

受信サーバーの`serve --bs2k --wol-idle 60`は必要なモジュールと設定を照合し、録画終了・後処理完了から60秒以上経過し、確立済みTCP接続がなければ本体を`freeze`へ移します。復帰後も60秒を取り直します。MACだけを待機させる旧オプションは削除しました。MAC単独の比較は`../lan_power.rs`で行います。
