# 公式更新ファイルBS1909122の展開

`extract_bs1909122.py`は、保存済みシステムの`/etc/dec_local`と公式`HD30_134.RVP`を入力に、親PC上で更新ファイルを展開します。Pythonの`cryptography`が必要です。対象2ファイルのSHA-256を固定して照合し、別の版は受け付けません。純正プログラムの実行や実機への接続は行いません。

```sh
rtk proxy python3 tools/contrib/firmware/extract_bs1909122.py \
  /path/to/dec_local /path/to/HD30_134.RVP /path/to/new-output
```

保存先は新規ディレクトリに限定します。純正復号処理と同じく、実行ファイル内のデータから鍵とIVを導出してAES-128-CBCを使用します。鍵の値はソース・出力・マニフェストへ記録しません。ヘッダーの識別子とCRC、領域の境界と重複、全6領域のCRCを確認してからファイルを書き出します。

## 対象コンテナー

公式配布の`HD30_BS1909122.zip`に含まれるRVPのSHA-256は`a8210d4aecf4c667cd7bfd0263eef7b351115cf76e07c8ce0c574f4409568ca8`でした。ヘッダーは先頭が`HEVC`で、先頭252バイトのCRC32と末尾4バイトのビッグエンディアン値が`0x0c2fab30`で一致しました。

|領域番号|格納位置|実データ長|取り出した形式|CRC32|
|---|---|---|---|---|
|2|`0x100`|64|元データのまま|`fad366e9`|
|1|`0x140`|2,213,493|AES-128-CBC復号後にgzip形式|`2016582c`|
|4|`0x21c7c0`|5,060,896|元データのまま|`346c4edb`|
|9|`0x6f00e0`|60,215,616|元データのまま|`d108f05d`|
|8|`0x405d220`|3,565,063|AES-128-CBC復号後にgzip形式|`1437eea9`|
|10|`0x43c3830`|134,992|AES-128-CBC復号後に先頭が`XDRM`|`cf15f367`|

領域1をgzip展開すると純正の更新ツールを含むtar、領域8は電子説明書のtarでした。領域4・9は先頭4KiBのエントロピーが約7.96bit/byteで、取り出した状態ではLinuxやSquashFSの識別子を確認できません。CRC一致は更新コンテナーからの取り出しが整合する証拠であり、領域4・9の内部を復号した結果ではありません。署名の検証や実機への適用も行っていません。
